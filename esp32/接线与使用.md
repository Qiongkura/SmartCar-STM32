# ESP32 手柄接收器

链路：手柄 → 蓝牙 → ESP32 → 串口 → STM32。
电脑只用于烧录和调试，运行时无需电脑。
此工程独立于 SmartCar，不修改小车其他模式。

## 接线

| ESP32 照片上的字 | 小车端 |
|---|---|
| D17（GPIO17） | PA10 / 原 HC-06 插口 TXD 对应引脚 |
| GND | 小车 GND |
| VIN | 稳压后的 5V，先测量确认 |

先拔掉 HC-06，不能让 HC-06 TXD 和 D17 同时连接 PA10。
D16 不需要接。RX0/TX0 留给 USB 串口。
照片 USB 在左时，D17 在下排，从 3V3 起数第 7 个。
VIN 不能接 11.1V 电池，也不要接原蓝牙插口的 3.3V。
首次调试用 USB 供电，只接 D17 和共地；USB 供电时不再接外部 VIN。
确认配对和方向后，改用小车稳压 5V 供电。

## 操作

手柄切到 Mobile / Bluetooth 档，开机，长按配对键 3 秒。
本次 X-Pro 已实测配对，RT 前进、LT 倒车、按住 LT 时左杆转向以及回中停车均通过此前 ESP32 日志验证，持续按 RT 约 6 秒未误停。当前 v2.2 新增松开扳机时左杆原地转向，软件检查和烧录校验已通过，见 verification.json。新增原地转向的实际轮子行为仍需试车确认。
首次配对成功后正常启动保留绑定。
需要清除绑定时，在程序运行后按住 BOOT 3 秒，再松开。不要按住 BOOT 上电，否则会进入下载模式。

小车选择模式七，按 K5 启动。连接后释放 RT/LT，左摇杆回中至少 0.3 秒。若刚连接还没有产生输入报告，轻推一次左摇杆再回中。

建议每次连接后先轻推左杆再回中，等待 0.3 秒，再按扳机。手柄连接时可能不主动发送静止报告，因此直接按扳机会被首次回中保护拦住，释放并回中后即可继续。

- RT：前进，按压深度决定前进目标速度；不需要按 RB。
- LT：减少前进指令，LT 大于 RT 时倒车。两扳机指令相等时没有前后移动指令，左杆仍可控制原地转向。
- 松开 RT/LT：停止前后移动；左杆拨左、拨右仍可原地转向。扳机松开且左杆回中时停车。
- 左摇杆左右：转向；后退的转向取反由小车处理，沿用原遥控器模式二。左杆上下、右杆、RB 不参与驾驶。
- B：停车并取消使能，需释放 RT/LT、左杆回中后才能继续。
- 当前 RT/LT 最大速度指令 78，对应车端目标速度 46.8 cm/s，约等于当前巡航 47 cm/s；按压深度仍决定速度。此值固定在 ESP32 中，不自动跟随小车巡航参数变化。
- 转向上限仍为 50%，最大转速约 60°/s，转向曲线与原版本一致。
- 蓝牙断联回调会发送停车指令，恢复后需要回中。已读到实际协商的 BLE 链路监督值 720 ms；从用户按关机到停车的实际延迟尚未计时。ESP32 自身失效时小车现有串口超时保护生效。

此 X-Pro 实测通过 BLE 连接，VID=2DC8、PID=901B，名称 8BitDo Ultimate。
手柄输入不变时不持续发 HID 报告，因此 AGE 增大是正常的，不能把它当成掉线。
断联判断使用蓝牙链路监督和连接回调，摇杆命令每 20 ms 继续转发。

USB 日志 115200；小车串口 9600 8N1，20 ms 一帧。
协议 AA 55 06 LIN ROT XOR，兼容车端现有防错位解析器。

## 工程

官方 ESP-IDF + Arduino + Bluepad32 模板，目标 esp32dev。使用 tools/build.ps1 编译，避免当前 PlatformIO 与模板的 SCons 版本冲突。
只编译 Arduino 核心，省略未使用的 WiFi、云服务等库及依赖。配置由 tools/configure_minimal.py 重现。
源程序 main/sketch.cpp，控制和协议 main/car_bridge.h。
编译、烧录和配对状态以验证记录为准。
